## [DEPENDENCY RFC] Auth Service — 16 nov 2026

**Estado (16 nov):** el lockfile y las dependencias experimentales están en `prototype/auth-g4`, **no en `dev`**. En el prototipo, `npm audit --audit-level=high` y `npm audit --omit=dev --audit-level=high` reportaron cero vulnerabilidades al comprobarlo; esto **no verifica dependencias futuras**. Reevaluar CVE y fijar nuevas versiones al implementar. No asumir que los paquetes del spike histórico están aprobados.

**Dependencias mínimas justificadas:** Node/Express 5 para HTTP; Prisma 7 + @prisma/client + @prisma/adapter-pg + pg para acceso PostgreSQL parametrizado y migraciones coordinadas; argon2 para Argon2id probado; zod para validar entradas HTTP; helmet para cabeceras de seguridad; express-rate-limit para limitar fuerza bruta (MVP un proceso); dotenv para configuración local fuera de Git. Desarrollo: prisma CLI, TypeScript, tsx y tipos Node/Express/PG.

**Evitar soluciones caseras:** no implementar hashing, drivers ni rate-limiter desde cero. Lógica de negocio propia: sesiones opacas, CSRF ligado a sesión, RBAC/ownership y bootstrap Admin. No instalar JWT, Passport, bcrypt, segundo ORM ni framework adicional.

**Gobierno de dependencias:** cuando se implemente código fuera de `dev`, fijar versiones exactas en lockfile, ejecutar npm audit --audit-level=high, documentar y resolver alertas relevantes antes de desplegar. No publicar secretos ni usar credenciales reales en pruebas.

**Regla COP3851:** los contratos OpenAPI + 3NF/FK/migraciones deben quedar revisados, validados y commiteados ANTES del primer controlador. El commit draft previo no implica G1 PASS.

## Flujo Git y evidencia de colaboración

- `main`: estable/protegida. `dev`: integración tras PR. `feat/*`: trabajo aislado; PR hacia `dev` con reviewer y verificación.
- Commits pequeños y significativos vinculados a FR/NFR o ticket. No auto-commit ni push por acción del agente sin permiso explícito.
- PR con objetivo, screenshot/log de evidencia cuando aplique, pruebas ejecutadas y riesgos. Mantener un changelog sencillo por release; no duplicar toda discusión en cinco archivos.
- Cada despliegue a S3 y EC2 relaciona `git SHA`, archivo checksum y fecha, sin llaves ni dumps de datos reales en S3 `releases/`.

## DoD — definición de terminado

Una funcionalidad solo está «Done» si: requisito identificado, permisos y errores implementados, prueba correspondiente ejecutada, README/OpenAPI al día y demo manual verificable. Cloud solo está «Done» si tiene evidencias reales de infraestructura desplegada, costos observados y cleanup plan; no por tener un diagrama.
