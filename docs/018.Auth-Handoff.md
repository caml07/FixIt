## Fuente de blocklist (27 nov 2026)

Para NFR-004 y NIST SP 800-63B-4, se selecciona como fuente inicial
el [corpus NCSC de SecLists](https://github.com/danielmiessler/SecLists/blob/c34ab251571b9c5e7c93d2e258d0c5b1a678a01c/Passwords/Common-Credentials/100k-most-used-passwords-NCSC.txt).
El [NCSC publico el analisis en abril de 2019](https://www.ncsc.gov.uk/news/most-hacked-passwords-revealed-as-uk-cyber-survey-exposes-gaps-in-online-security)
a partir de contrasenas previamente comprometidas. El repositorio SecLists
declara [licencia MIT](https://github.com/danielmiessler/SecLists/blob/c34ab251571b9c5e7c93d2e258d0c5b1a678a01c/LICENSE);
no se redistribuye el corpus en Git ni se presume una licencia especifica
adicional sobre sus datos originales.

Descargar la revision fija, no `master`, desde la raiz del repositorio:

```sh
mkdir -p generated/security
curl --fail --location --output generated/security/password-blocklist.txt https://raw.githubusercontent.com/danielmiessler/SecLists/c34ab251571b9c5e7c93d2e258d0c5b1a678a01c/Passwords/Common-Credentials/100k-most-used-passwords-NCSC.txt
sha256sum generated/security/password-blocklist.txt
```

En PowerShell, crear el directorio con `New-Item -ItemType Directory -Force generated/security`,
usar `curl.exe` con los mismos argumentos y verificar con
`Get-FileHash generated/security/password-blocklist.txt -Algorithm SHA256`.
El SHA-256 esperado es `c2e5696882c603b76bb67a47ee970897e5a76fc4c3f5547abe3d0ca340c576e0`.
No utilizar el archivo si no coincide. `generated/` ya esta excluido de Git.
Configurar `AUTH_PASSWORD_BLOCKLIST_FILE` con la ruta absoluta del archivo
local; para contenedores, montarlo como archivo de solo lectura y configurar
la ruta dentro del contenedor. No realizar descargas al iniciar Auth ni enviar
contrasenas a terceros.

Verificacion local: 835538 bytes, 99839 lineas no vacias, 97746 entradas
unicas tras NFC y minusculas, 329 compatibles con la politica actual de
longitud (15 caracteres minimo y hasta 1024 bytes). La funcion `passwordError`
extraida de `feat/auth` en `f145a9d` rechazo una entrada elegible real que no
rechazaba sin el corpus, y acepto una frase sintetica no listada. No se
imprimieron las entradas. No se ejecuto la ruta HTTP de activacion ni el
cargador completo de Auth contra este archivo.

Es una fuente inicial para el MVP, no una lista exhaustiva ni una certificacion
NIST. Su fecha y baja cobertura de contrasenas largas justifican revisar una
fuente mas reciente y terminos previsibles del servicio antes de produccion.
Para actualizar, revisar procedencia/licencia de la nueva revision, fijar su
commit y SHA-256, repetir validacion UTF-8, cobertura y pruebas de rechazo y
aceptacion; reemplazar el archivo solo tras validarlo y reiniciar Auth para
cargarlo. Revisar cobertura junto con rate limiting, sin cambiar OpenAPI ni SQL.
