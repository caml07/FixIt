## Acuerdos confirmados vs. hipótesis

**Seleccionado por usuario (10-11 nov; equipo pendiente):** IT Help Desk con chat por ticket y claim; **tres servicios Auth/Tickets/Chat**, PostgreSQL compartida en esquemas `auth`/`tickets`, MongoDB para mensajes, REST para permisos y **NATS JetStream para eventos** con consistencia eventual. Sesiones opacas, seeder del primer Admin y política NIST; el algoritmo de hashing sigue por resolver. La propuesta vigente se consulta en [010.G1](010.G1-Contracts.md), [ADR-005](adr/ADR-005-three-services-opaque-sessions.md) y [CONTEXT](../CONTEXT.md); lo anterior de monolito/dos servicios es **historial**, no prioridad de implementación.

**Cloud comunicado por el usuario (11 nov):** Marvin acepta **una VPC y una EC2** y espera S3. La **modalidad exacta de S3** y los formatos/fechas de evidencia siguen pendientes; llevar [004.Cloud](004.Cloud.md) y [011.Gates](011.Gates.md) a la revisión del 12 nov. Cloud corresponde a caml07 y Valeria; Rina participa en Web II y no cursa Cloud. **Ningun recurso AWS ni producto se ha desplegado**.

## Reglas de mantenimiento

- Cambios de alcance: editar 001 y marcar el ADR relacionado.
- Comportamiento: **002**; diseño vigente y contratos conceptuales: **010**; AWS/precios: **004**; ejecución: **005**. `003` es alternativa historica.
- Cada FR/NFR tiene ID estable y prueba prevista; no renumerar IDs existentes.
- Cada ADR describe **estado** (proposed/accepted/superseded) y alternativa descartada; no convertir un borrador en acuerdo sin confirmación.
- No crear implementación, IAM, VPC, buckets ni cuentas por el hecho de estar descritos aquí.
- GitHub es la fuente de verdad del código y documentación. S3 no sustituye Git; confirmar con Marvin si pide **website publico**, **versionado privado** o ambos antes de fijar la evidencia.
- Documentos sin código ni infraestructura se etiquetan **diseño / no verificado**.
